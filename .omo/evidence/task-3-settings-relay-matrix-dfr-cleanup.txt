### 2. Timestamps reflect actual relay transitions (not spurious in-band hysteresis output)

**Source:** `Infrastructure/automation-service/app/control/device_controller.py` (Todo 2 fix)

Todo 2 changed `_log_control_action` line 767 from:
```python
new_state = 1 if control_output > 0.5 else 0
```
to:
```python
new_state = self.relay_manager.get_device_state(location, cluster, device_name) or 0
```

This ensures `new_state` is the **actual** relay state after hysteresis is applied, not the raw control output. The `control_action_repo.log_control_action` short-circuits on `old_state == new_state`, so no spurious log is written when hysteresis preserves the state.

The timestamps in the endpoint come from:
1. Redis `RELAY_TIMESTAMPS` — updated by `hardware_batch` only when a channel **actually changes state**
2. DB fallback `get_last_changed_per_channel()` — queries the `control_history` table where only real transitions are logged

Therefore, the timestamps accurately reflect physical relay transitions, not in-band hysteresis noise. ✓

Coverage behavior
- CaggWatermarkCache keeps an instance-local process-memory dict keyed exclusively by the
  known CAGG relation names. Entries are immutable CaggWatermarkEntry values with
  watermark and monotonic fetched_at fields; the documented TTL constant is 5.0 seconds.
- A fresh cache entry avoids the watermark query. Expiry refreshes it and atomically replaces
  the immutable entry. The repository is the service singleton in normal execution; tests may
  inject an independent cache and monotonic clock without changing production behavior.
- _require_cagg_coverage remains mandatory and returns watermark minus the source bucket width.
  Tiered SQL binds that safe complete-tail upper bound ($8 without point bucketing, $9 with it),
  with no correlated SELECT max(bucket) subquery. The incomplete watermark bucket is excluded.
- Long-window CAGG statistics now calculate sample standard deviation from value_sum,
  value_sum_squares, and sample_count. SQL returns 0 for sample_count below 2, preserving the
  nonnegative legacy serialization contract. Formula assertions use 1e-9 relative tolerance.

Watermark-query proof
- Fresh-cache test: two coverage reads => 1 fake watermark fetch.
- Expiry/advance test: two coverage reads after monotonic time advances 5.1 seconds => 2 fake
  watermark fetches and the returned complete-tail bound advances by one minute.
- Relation-isolation test: one-minute, five-minute, then one-minute coverage reads => 2 fake
  watermark fetches (one per relation).

Stddev quality matrix
- Raw measurement SQL: exact (native STDDEV_SAMP).
- 5-minute CAGG with value_sum/value_sum_squares/sample_count: exact.
- A source without sufficient statistics: the existing explicit approximate serialization path
  remains available and is contract-tested; no deployed monitoring statistics source lacks the
  required sufficient-stat columns.

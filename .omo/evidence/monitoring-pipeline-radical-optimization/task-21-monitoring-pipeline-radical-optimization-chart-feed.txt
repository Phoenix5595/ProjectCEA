# T21 — Chart-only monitoring feed

## Delivered

- Added `src/features/monitoring/charts/MonitoringChartFeed.ts` as the typed,
  per-chart controller. It keeps a stable structural snapshot containing the
  selected range identity, series shape/count, and theme revision while
  exposing the latest bounded `AlignedData` buffer separately.
- `createMonitoringPanelChartFeed()` owns a T20 `PanelAlignment` instance and
  feeds it from a `MonitoringStore` subscription. It therefore reuses T20's
  static-base/live-tail split without reproducing alignment logic.
- `UPlotChart` reads structure with `useSyncExternalStore`, subscribes to feed
  revisions imperatively, and sends non-structural updates through
  `plot.setData(toUPlotData(feed.getData()), false)`. Structural range/series
  changes and theme flips take the existing destroy/recreate path.
- Flower and Vegetation pages retain their ordinary `useMonitoringStore`
  snapshots for toolbars, status, tables, and chart visibility while their
  stable feeds drive the two chart canvases.

## Acceptance coverage

- `MonitoringChartFeed.test.ts`: a live-buffer publish preserves the exact
  structural snapshot identity and an unsubscribe prevents further listener
  notifications.
- `UPlotChart.test.tsx`: a real function-component render counter stays at one
  across 120 feed ticks; mocked uPlot receives exactly 120 bounded
  `setData(..., false)` calls and is not recreated. The same test locks
  unsubscribe cleanup plus exactly one recreation for a series-count change
  and for a range-identity change. Existing lifecycle coverage locks theme
  recreation.
- Page and table tests pass with the chart feeds connected, preserving normal
  React ownership of status/table surfaces.

Task 14 — semantic point budgeting for control history

Scope
- Implemented only monitoring-service control-history reads and their tests.
- No sensor-side files, database schema files, hardware/PID authority code, dependencies, or production resources were changed.
- No git command was run.

Behavior
- `max_points` is passed from the history route through RuntimeControlReads into ControlHistoryRepository.
- Unbudgeted reads retain the raw `effective_setpoints` plus 1-minute automation-state SQL and produce the characterization-pinned JSON envelope exactly.
- Budgeted reads choose existing sources by duration: raw setpoints/1-minute state below two hours, 1-minute setpoints/state at two hours through under one day, and 5-minute setpoints/state at one day or longer.
- CAGG queries use their `*_last` columns directly. CAGG setpoint series carry `is_aggregated=true` provenance.
- Applied metadata is constructed by the repository from the selected source interval and `derive_interval_seconds`; the route does not overwrite it.
- Climate/light held targets become predecessor-plus-transition `steps`; raw ramp runs become explicit `linear` endpoint segments. Device and PID rows keep observed transition rows only. Photoperiod removes only consecutive rows whose phase, mode IDs, and snapshot version are identical.
- A null raw target reading becomes an unavailable null step under budgeting, so a hold is not bridged over the gap. No values are averaged.
- The predecessor is counted inside the per-series budget. When more observed transitions exist than the requested capacity, retained rows are existing first/last transition facts; no extra sentinel is emitted and no categorical string is synthesized.

Characterization
- `test_history_without_budget_matches_characterized_legacy_envelope` asserts the full Pydantic JSON serialization from a fake database before and after the refactor.

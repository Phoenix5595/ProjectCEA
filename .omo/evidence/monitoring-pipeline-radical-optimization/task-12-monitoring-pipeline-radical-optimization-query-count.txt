Task 12 — Collapse per-node sensor fan-out into one bounded room query
Date: 2026-08-24

Implementation
--------------
- `sensor_sql.py` binds a fixed two-slot `VALUES ($2, $3), ($4, $5)` node/pattern
  CTE. Every raw, raw-budgeted, CAGG, CAGG-budgeted, and statistics statement
  joins it with `sensor.name LIKE node_patterns.pattern`, selects its canonical
  node, and groups by that node. Empty second slots make Veg main-only.
- `sensor_rows.py` derives the two bounded slots from canonical topology and
  converts SQL-labeled rows back to legacy topology order. No unmatched pattern
  can appear because the query uses an inner mapping join.
- `sensor_repository.py` performs exactly one series fetch and one statistics
  fetch per repository call, then splits by returned SQL node. T13 coverage and
  watermark operations remain outside this change.

Characterization and query-count proof
--------------------------------------
- Before implementation, `tests/test_sensor_node_fanout.py` failed as intended:
  Flower series fetch count was 2, Flower statistics fetch count was 2, and
  Flower budgeted-series fetch count was 2.
- After implementation, `test_series_fetches_flower_nodes_once_and_excludes_foreign_pattern`
  proves one Flower series fetch, front/back attribution, and foreign-pattern
  exclusion.
- `test_statistics_fetches_flower_nodes_once` proves one Flower statistics fetch

- `test_flower_range_uses_one_series_and_one_statistics_fetch` exercises the

- `test_series_uses_main_for_veg`, `test_series_never_fetches_unknown_room`, and
  `test_budgeted_series_remains_within_max_points_after_node_merge` preserve Veg
  main-only attribution, unknown-room no-fetch behavior, and the point budget.
- Existing no-budget Flower/Veg snapshots remain locked in
